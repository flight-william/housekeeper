## Code review (Opus): merge after fixes

The coordinator reproduced M1 and M2 with semgrep 1.187.0 before ruling. Rulings follow each
finding.

### Medium
1. **M1: r9-ts-ignore misses forms tsc honors**: `/** @ts-ignore */` and a block comment
   whose last line is ` * @ts-ignore */` (tsc suppresses the error; Semgrep reported nothing).
   - **Ruling: fix (root cause).** Match the way TypeScript reads the directive: any run of
     `/`, `*` and space after the comment opener, or a line starting with `*` inside a block
     comment. Add both forms to the planted fixture.
2. **M2: chained test modifiers pass**: `it.concurrent.skip`, `test.skip.failing`,
   `test.concurrent.only.each`, `specify.skip`, `xcontext`, `xspecify` and others gave no
   finding. The rules listed exact chains.
   - **Ruling: fix (root cause).** Match any call whose callee is a test name followed by a
     chain that holds `skip`, `skipIf` or `only`, by a metavariable regex, not a list of
     chains. Add Mocha's `specify`, `xcontext`, `xspecify`. Plant the chained forms.

### Low / Medium
3. **L1: the `.*` globs protect files no tool reads**, and the case check cannot be cleared
   by an approval line: `docs/Prettier.config.md` is an R9 settings-case finding.
   - **Ruling: fix.** List the extensions each tool loads (`eslint.config.{js,mjs,cjs,ts,mts,cts}`,
     `prettier.config.*` and `.prettierrc.*` the same way, plus `.prettierrc` and its
     json/yaml/toml/json5 forms) and `tsconfig.json` plus `tsconfig.*.json`. Drop `.eslintrc*`
     and `.eslintignore`: house's ESLint lane requires a flat `eslint.config.*` (no flat config
     is an R2 finding), and flat config reads neither, so they never govern a passing run.

### Low
4. **L2: JSX text** such as `<div>// @ts-ignore text</div>` is reported. **Ruling: leave.** It
   errs toward a finding, and the text is rare; noted in the README.
5. **L3: `jsconfig.json`, `vitest.config.*`, `jest.config.*` are not protected.** **Ruling:
   leave, named for a later release.** Adjacent to the ask.
6. **L4: src/adapter.rs `JS_EXTENSIONS` comment names only Prettier, ESLint and r3.** **Ruling:
   fix**; Semgrep now uses it.
7. **L5: "own list plus JS_EXTENSIONS" is composed in three places**, and semgrep.rs repeats
   `.sh`/`.bash`. **Ruling: leave**, pre-existing pattern; a one-definition pass of its own.
8. **L6: fixture gaps** (M1 and M2 forms, a .tsx file). **Ruling: fixed with M1 and M2.** The
   vacuous pass without semgrep is pre-existing (CI installs it).

### For the owner
- **package.json is protected**, so every dependency bump, Dependabot's and Renovate's
  included, needs the approval line, and the merge stage judges each commit of such a pull
  request. The owner chose the option that named package.json; this consequence is put to
  them with the release.
- **Repos that already have a CODEOWNERS** do not get the new globs: `house init` leaves an
  existing file alone. The 0.5.0 release message says so.
